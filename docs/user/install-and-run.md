# 安装与使用（普通用户版）

这份说明面向「在自己电脑上用」的人，不需要会写代码。所有东西都跑在你自己的电脑上：
没有服务器、没有账号体系、不上传任何资料。

## 这是什么

jobkit 是一个本地求职助手。它帮你把「找工作」里最耗时的整理工作做完：

- 记下你自己的资料（经历、技能、期望）、求职方案（想找什么岗位、在哪些城市）
- 按关键词和城市读岗位列表与岗位详情，给出候选清单，并说明**为什么**推这一条
- 针对某条岗位/某段对话生成回复草稿，标明草稿依据了你资料里的哪几句
- 记录你处理到哪一步，导出成文件留存

## 能做什么、不能做什么

能做：

- 读岗位、看详情、按条件筛，给出匹配理由与不匹配的地方
- 出草稿（打招呼、回复），草稿会写清引用自你的哪些资料
- 记录进度（待处理 / 已人工处理）、导出记录
- 备份整个数据库

不能做（这是设计上的限制，不是没做完）：

- **不会自己把消息发出去。** 发送功能默认是关闭的：所有对外写入都要经过一道闸门，
  没有你显式给出的一次性授权，请求会被拒绝；即使有授权，也只在你确认目标之后执行一次。
  正常使用流程就是：草稿 → 你自己核对 → 你到平台上手动发 → 回来登记结果。
- 不会绕过平台的限制。连续读不到页面时会停下来交给你，不会自动重试。
- 不会替你承诺薪资、不会编造经历。资料里没有依据时，草稿会提示「需人工处理」。
- 不是多用户系统。它只有「本机一个人用」这一种模式，界面里的企业/账号只是本地分组，
  不代表已经连接或认证了任何平台账号。

## 安装

### 1. 装 Python 3.11 或更新

到 python.org 下载安装包，安装时勾选 **Add Python to PATH**。装完在命令行里确认：

```bat
python --version
```

显示 3.11 或更高就行。低于 3.11 请升级：旧版本装不上依赖。

### 2. 装依赖

在本项目目录下（能看到 `main.py` 的那个目录）执行：

```bat
python -m pip install -r requirements.txt
```

这是必需的几个包（Web 框架、请求库、加密库）。

### 3. OCR（可选）

OCR 用来从截图里读工资、学历这类文字。用不到可以不装；装了才能读图片。

```bat
python -m pip install -r requirements-ocr.txt
```

它依赖 Windows 的 VC++ 运行库。如果装完仍然报 `DLL load failed`，去微软官网装
「Visual C++ Redistributable（x64）」再试。OCR 没装或没跑起来时，除读图以外的功能照常可用。

> 检查装好没有：跑一次体检（见下面「出问题」一节），它会逐项真导入一遍，
> 而不是只看 `pip install` 有没有报错。

## 启动与停止

启动（在项目目录下）：

```bat
python main.py serve --host 127.0.0.1 --port 18770
```

然后在浏览器打开 <http://127.0.0.1:18770/workspace>。

停止：回到运行它的那个命令行窗口，按 `Ctrl+C`。**不要**直接用任务管理器乱杀 python 进程，
那样会连带杀掉别的程序。

### 端口被占用怎么办

`18770` 上已经有程序在监听时会启动失败。两种处理：

1. 先确认那个程序是不是 jobkit 自己（可能上次没关干净）。体检脚本会告诉你：
   `python scripts/check-install.py` 会显示这个端口上是 jobkit 还是别的程序。
2. 换一个端口启动，例如：

   ```bat
   python main.py serve --port 18771
   ```

   换端口后，界面地址也要跟着改成 `http://127.0.0.1:18771/workspace`。

## 第一次使用

按这个顺序走一遍就够了：

1. **填资料**：打开工作区，填写本人资料（经历、技能、期望岗位、城市），核对后保存。
   资料是后面所有草稿的依据，写具体一点，草稿才有东西可引用。
2. **定求职方案**：写下想找的岗位方向和城市范围。方案决定搜什么、按什么排序。
3. **搜索岗位**：在界面上按关键词 + 城市搜索；也可以用命令行：

   ```bat
   python main.py job-search --keyword 后端开发 --city 杭州 --pages 3
   ```

   一页一页读，读到平台限制（连续读不到详情）会自己停下并告诉你。
4. **看候选与理由**：每条候选都带匹配理由和不匹配点。理由是根据你的资料算出来的，
   觉得不对就回去改资料，不要只改结论。
5. **出草稿**：挑中意的岗位/对话，生成回复草稿。草稿会标注引用了你资料里的哪几句。
6. **人工核对**：逐条看草稿，改措辞（改过的版本会单独保存，原稿也留着）。
   页面上标「需人工处理」的，说明依据不足，需要你自己写。
7. **到平台上自己发**：复制草稿，回原平台核对对象（人、岗位、公司）后自己点发送。
8. **回来登记结果**：发送后回到工作区，标记「已人工处理」；如果发失败或结果不确定，
   按界面提示登记真实结果。这一步是给你自己留证据的，也是系统的安全闸门：
   有「结果没核对完」的记录时，系统不会允许再对同一对象动作。

## 出问题：按顺序跑三个自检

三条命令都是**只读**的：不改数据、不装包、不启停服务。按顺序跑，先看第一条。

### 1. 一键体检（先跑这个）

```bat
python scripts/check-install.py
```

它一次检查五件事：Python 版本与依赖、端口有没有被占、数据库能不能读写、
浏览器调试口通不通、跑着的程序是不是当前这份代码。输出一堆 JSON 行，
最后一段中文总结就是给你看的：标 `[OK]` 的没问题，标 `[要处理]` 的要动手，
标 `[提示]` 的只是说明（比如「服务还没启动」）。

### 2. 运行版本 vs 磁盘

```bat
python scripts/check-version.py
```

回答一个问题：**正在跑的那个服务和硬盘上的代码是不是同一份**。
改完代码没重启、或从别的目录启动过，就会不一致。

### 3. 依赖逐项真导入

```bat
python scripts/check-deps.py
```

把 `requirements*.txt` 里每一项真的 import 一次，并检查 OCR 的模型文件与引擎能不能起来。
OCR 缺失只是提示（加 `--allow-missing-ocr` 明确当成可选）。

### 三个脚本的退出码都是这三档

| 退出码 | 意思 | 你该做什么 |
| --- | --- | --- |
| `0` | 检查跑完，结论正常 | 不用管 |
| `2` | 检查跑完，**有需要你看的事** | 看报告里标「要处理」的行 |
| `1` | 检查本身没跑完（文件缺了、连不上、脚本报错） | 先解决「跑不起来」，再看结论 |

`2` 不是「脚本坏了」，是「东西有问题，脚本如实告诉你了」。在命令行里看退出码：
`echo %errorlevel%`（cmd）或 `$LASTEXITCODE`（PowerShell）。

## 数据在哪、怎么不丢

- 数据都在一个 SQLite 文件里：项目目录下的 `jobkit.db`（如果设置过环境变量
  `JOBKIT_DB`，就是那个路径指向的文件）。
- 备份（推荐定期做，动数据库之前也做一次）：

  ```bat
  python main.py backup --confirm-all-workspaces
  ```

  备份会存到数据库所在目录的 `.jobkit-backups/<备份编号>/` 下，是一条独立的副本，
  并生成一份清单文件（含字节数与校验值）。用返回的编号可以校验这份备份：

  ```bat
  python main.py backup-check --backup-id <上一步返回的编号>
  ```

- 工作区里的「导出当前工作区记录」是另一回事：它导出的是**你看到的消息、草稿与资料**，
  方便留存或给别人看，不是完整数据库备份，也不能用来整体恢复数据库。
- **不要手动删或「清理」`jobkit.db`**，也不要在它正被使用时用别的工具改写它。
  删掉就是所有记录没了；需要腾空间请用备份 + 导出的方式。

## 隐私边界

- 对话与草稿存在**你自己的**数据库文件里，不上传。
- 运行记录（谁在什么时候做了什么操作）**刻意不存消息正文、资料内容、模型推理过程和凭据**，
  只留操作名、状态与时间；这类操作痕迹默认只保留最近 30 天。
- 导出的 JSON 是明文，包含消息原话、备注和资料，请自己保管好。它**不包含**浏览器 Cookie /
  登录态，也**不包含**简历文件本身（简历单独存在 `data/resume.txt`）。
- `/version` 这类只读接口只暴露文件名、短哈希、版本号和启动时间，
  不含绝对路径、用户名、正文或凭据。
- 需要模型服务（可选）时，只有你配置并主动触发的那次请求会带上你选中的文本；
  不配置模型时，草稿由本地规则生成，不联网。

## 常见问题

**启动后打开页面是空白 / 401**：说明浏览器没拿到这次启动的会话。
直接访问 <http://127.0.0.1:18770/>（首页）进入，不要手输深层链接；还不行就重启服务再试。

**体检说「运行版本落后于磁盘」**：运行中的进程加载的是旧代码。
关掉它（`Ctrl+C`）重新 `python main.py serve`，再跑一次体检。

**体检说「有 N 个外部动作没核对完」**：上一次真发出去（或结果不确定）的记录还没登记结果。
先跑 `python main.py outcome list` 看清楚，再用 `python main.py outcome resolve <记录编号> <结论> --by 你的名字`
登记真实结论（结论三选一：已送达 / 未送达 / 确认重复；详见 `python main.py outcome --help`）。
在这一步做完之前，系统会拦住对同一对象的再次动作——这是故意的。

**体检说「浏览器调试口 9222 未开」**：只能用命令行与只读功能（搜索、草稿、查看）。
需要读写页面时，用项目自带的登录脚本拉起带调试端口的浏览器：

```bat
python boss_login.py
```

弹出的窗口里扫码登录，登录窗口保持打开（后续动作要靠它）。不想动浏览器时，
这条提示可以忽略。

**Python 太旧**：装 3.11 或更新的版本，重新装依赖，再跑体检。
